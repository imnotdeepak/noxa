# Instagram Safari filter prototype

This Safari Web Extension prototype is now embedded in the Noxa iOS app behind an off-by-default per-site choice and an active subscription expiry check. It is labeled experimental in Settings and must not be presented as confirmed protection until Safari behavior is observed on a physical device.

It requests access only to `instagram.com` and `www.instagram.com`. The content script hides links to `/reel/`, `/reels/`, and `/explore/`, except Instagram's `/explore/search/` route, and covers Reels and Explore direct routes with a way back to the main feed. Feed articles containing a Reel permalink are hidden as a whole. The main feed, messages, search, and profiles are left available by route. On October 23, signed-in Safari on the paired iPhone showed the feed, messages, a usable search field, and the owner's profile while direct Reels and Explore routes showed Noxa's pause screen. That check found and corrected a search-route false positive. Instagram can change its markup and navigation behavior at any time. Feed Reels without a matching permalink or article container may still be visible.

Before release, finish checking navigation after login, localization, extension permission loss, subscription expiry, and Reels embedded in the feed. The extension's native message handler reads the off-by-default toggle and RevenueCat entitlement expiry from the app's shared container; it returns disabled when either is missing or expired. Safari must also be enabled and granted instagram.com access by the user. On iOS 26.2 or later the app can show whether the extension itself is enabled; that state alone cannot prove that Instagram page access was granted or the filter worked.

The manifest requests only Instagram host access. When the script reaches an Instagram page, it sends its host to the native handler; the handler records a local timestamp only after confirming the site, selected mode, and paid entitlement. Settings shows whether this connection happened recently. It does not claim that a connection proves every element was hidden. When no recent connection exists, Settings offers permission guidance and Full Block.

Apple's packaging and permission documentation: https://developer.apple.com/documentation/safariservices/packaging-a-web-extension-for-safari and https://developer.apple.com/documentation/safariservices/managing-safari-web-extension-permissions
